# Архитектура Sushimi

Sushimi — модульный монолит для отдельной установки у каждой доставки. Публичная витрина, CRM и серверные обработчики находятся в одном Next.js-приложении, но доменная логика разделена по модулям.

## Границы

- `src/app/(storefront)` — публичные маршруты магазина.
- `src/app/admin` — интерфейс сотрудников. Перед подключением реальных данных должен быть закрыт авторизацией.
- `src/app/api` — HTTP-точки интеграции и health check.
- `src/modules/<module>/domain` — типы и правила предметной области без React и базы данных.
- `src/modules/<module>/application` — сценарии использования и границы репозиториев.
- `src/modules/<module>/data` — реализации хранилищ и временные демонстрационные данные.
- `src/modules/<module>/ui` — React-компоненты конкретного модуля.
- `src/server` — инфраструктура, доступная только серверному коду.

## Основные модули

1. `catalog`: категории, товары, доступность и цены.
2. `orders`: оформление заказа, зафиксированные позиции и жизненный цикл статусов.
3. `delivery`: зоны, минимальная сумма и стоимость доставки.
4. `identity`: сотрудники, роли и сессии (следующий этап).
5. `notifications`: Telegram/SMS и повторные попытки (следующий этап).

Денежные значения хранятся целыми числами в копейках. В позиции заказа копируются название и цена товара: последующее изменение меню не меняет историю заказа.

## Правила зависимостей

`ui -> application -> domain`; инфраструктура реализует интерфейсы application-слоя. Домен не импортирует Next.js, React или Drizzle. Публичная витрина не обращается к таблицам напрямую.

## Реализованный вертикальный срез

PostgreSQL-каталог → корзина → серверная проверка цены и доставки → создание заказа → новый заказ в CRM.

Следующие границы: авторизация сотрудников и роли, изменение статусов заказа, управление каталогом и уведомления.
